# Codex Jev 0.5.1 release notes

This patch release updates the version-pinned Codex webview script so the search relevance switch and cutoff appear in **Codex settings → Jev**. Its bridge now validates and forwards both values when settings are saved. The paired VS Code control is version 0.4.1. An existing patched Codex extension also needs `patch_codex_webview.py update`; installing the VSIX alone cannot replace the injected settings script. Reload VS Code manually after both updates.

Search results now receive a third independent Noul probability: whether each match or path helps the current task. The optional relevance guard can only keep more lines; it starts in preview mode, with probabilities visible in the panel and private receipt. Locally protected lines are no longer sent as Jev targets, reducing request work. The hook still requires conservative omission and exact-text gates, retains diagnostics and unjudged lines, and returns the full result on a failed batch.

The Rust quality CLI reports evidence loss by route and split and replays stricter line gates plus the search relevance guard against reviewed receipts. No settings change automatically. The Linux x86_64 plugin package contains a Rust executable and requires no Python at hook runtime. The VS Code control shows five recent judged lines, the latest line's animated probability bars, keep reasons, and search relevance where applicable. Config schema 2 preserves existing selections and adds a disabled-by-default search policy.
