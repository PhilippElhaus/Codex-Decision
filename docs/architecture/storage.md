# Storage and publication

Advisory configuration lives in private `PLUGIN_DATA/assistance.json`. Explicit advisory requests have separate health and metadata under `PLUGIN_DATA/assistance/` or the selected session's `assistance/` child. Their counters are independent of filtering. Model-request observations use bounded `logs/model-requests.jsonl` files. Opt-in Stop review uses a bounded content-bearing `logs/completion-evidence.json` snapshot with turn identity, incompleteness, and continuation markers. See [advisory architecture](assistance.md), [telemetry](../operations/telemetry.md), and [completion verification](../reference/completion-verification.md).

A completed relevance batch can publish a version-6 snapshot containing every source line in order, including earlier judgments, protected lines, and pending lines. Outputs below 1,000 lines publish every batch. Larger outputs publish the first and final batches and intermediate updates at most once per second. Every completed judgment remains in the final snapshot and receipt. Judged rows carry actual task relevance. Protected and pending rows carry no probability. Snapshots are bounded to 10,000 lines and 8 MiB. The panel validates row counts against totals and can still read version-3/4/5 historical snapshots. Receipts use version 3; historical version-2 receipts remain readable. Private batch 0 exists only when classification ran; batches 1 through N record line judgments. Manifests record the class, actual request count, API token usage when supplied, elapsed time, policy, and line decisions. Kept classification-only results record their distribution and usage in activity events.

Replacement saves the exact original under `PLUGIN_DATA/outputs/<session-hash>/<call-hash>.txt` before returning retained spans, omission counts, and its path. Monitor leaves the result unchanged. Replacement needs a supported text response, actual user task, more than 256 bytes saved and more than a 20% reduction after all headers. A known command object or code-mode text array also saves its exact typed value in the adjacent `.json` file. The `.txt` file contains the complete readable view. Metadata stays protected in that view. Both paths appear in replacement feedback. A private bounded journal coordinates receipts, stats, final snapshots, and the completion event. Prepared publications roll back; an explicit atomic committed marker finalizes them. Consumers expose prior committed images during preparation. Later cleanup or telemetry failure cannot cancel a committed replacement. An exact original pair can be reused by an identical retry; a permanent session originals lock holds its lease through publication or rollback. Saved originals remain until manually removed; managed logs obey existing retention limits.

Immutable batch evidence is encoded and synced to private pending files before the session lock. The transaction publishes those bytes under the lock. Panel rows are constructed before locking; their publication timestamp is set under the lock. Pending files are removed after completion. Crash recovery removes only recognized private regular files older than the hook's 60-second outer timeout. Fresh, unknown, linked, and nonregular files are preserved. A log folder on another filesystem uses the existing private atomic-write fallback.

Receipt, batch, and panel encoders borrow existing evidence. Their bounded writers preserve canonical JSON field order and stop at the existing byte limits. Buffer growth stays within those limits. Bulk receipt and panel bytes are prepared before the log lock. A serde marker records the timestamp byte range; it does not search source text. Publication inserts the locked UTC timestamp and checks the final size before writing. Source hashes and character counts are also computed before the lock. Source spans and diagnostic protection have frozen baseline parity checks. Unix directory creation applies mode 700 at creation, so concurrent initialization cannot observe a temporary public mode. Event and lock files must be regular files on the opened handle. Unix opens reject links and use nonblocking access.

Retention reads at most the last 1 MiB of the event log through one regular, no-follow handle. It keeps complete JSONL tail records. Receipt and batch pruning accepts only canonical managed filenames and, on Unix, private files owned by the current user. Unknown files, public files, links, and special files remain intact. Saved originals do not participate in automatic retention.

Private health records count durable invocation, request-intent, received-response, validated-answer, failure, cancellation, and named skip entries. Registration does not establish provider receipt. Classification completion and its later health skip entry have separate commit points. Stats distinguish committed evaluations, previews, replacements, proposed omissions, and actual omissions. `decisionctl activity --data-dir <PLUGIN_DATA> --session <thread-id>` reads aggregate records and, when needed, bounded retained activity. It does not read a key, task, or raw receipt. Fresh scheme-1 history starts at exact zero; legacy and unresolved request outcomes retain explicit lower bounds or unknown values. Overflow and ambiguous records are rejected before publication. See [measurement](../operations/measurement.md) for counter boundaries.

See [telemetry](../operations/telemetry.md) for content-free request records.
