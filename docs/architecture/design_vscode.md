# VS Code control and panel

The optional control adds one on/off button beside the Codex composer and a **Decision** tab in VS Code's bottom panel. A version-pinned bridge observes Codex's internal router and publishes the active local thread ID; the webview URL alone is not reliable. The extension hashes that ID into a directory name and reads only that session's config, activity, statistics, health, and latest decision. It creates an enabled config once for a new local thread, then preserves the user's changes. A focused composer selects the panel’s session; background status messages cannot switch it. Route and focus events request an immediate refresh. Switching threads clears the view’s activity. On the new-thread or home screen, no session exists yet: the control stays neutral and disables the button. A local thread route with an unreadable ID remains a configuration error instead of writing a plugin-wide flag. The API key is intentionally shared by the local installation.

The composer indicator reports the saved key and Decision API endpoint. The control sends a small synthetic predicate or Noul request. When enabled, green means it received a valid Decision answer; red means the key or request failed; amber means the request is pending. The button is gray when off or without a thread. The probe runs without a session ID and when Decision is off. The hook writes `logs/hook-health.json` whenever it runs on an enabled session, including normal skips, completed decisions, and errors. Hook, config, and status-file errors appear in the session activity tooltip. The tooltip explains when filtering is off and shows pending API checks. It is hidden without a thread. An API check does not verify hook trust. Review `/hooks` after a hook update.

The panel reads `PLUGIN_DATA/sessions/<hash>/logs/latest-decision.json` while visible and shows this thread's API request count, skip count, and latest skip or error until a line decision exists. It accepts current version-6 relevance snapshots and historical version-3/4/5 snapshots. A current snapshot contains every source line in order, with cumulative judgments from all completed batches, protected lines, and pending lines. Each row has a bounded excerpt, Keep/Omit action, and keep reason. Protected and pending rows show an em dash instead of a probability. The reader enforces a 10,000-line and 8 MiB bound and checks row counts against totals. The batch count can exceed one and totals count actual completed requests and include classification only when it ran. Current rows show the actual 0–1 task-relevance predicate or Noul. Historical rows retain their visual retention index, which is not a Decision probability. Blue rows show omissions; gold rows show keeps. The header distinguishes filtered output from a preview that kept full output. It validates the full directory chain and never reads another session’s panel file or a full receipt. Unchanged snapshots are cached after metadata checks. Composer status, hook activity, and visible-panel fallback checks run once per second; layout changes use observers with a slower fallback. An unreadable decision is shown as a health fault in the composer, keeping the panel itself quiet.

**Codex settings → Decision** stores Monitor/Filter mode, one shared relevance cutoff, and log retention in shared `PLUGIN_DATA/settings.json`. The Rust hook applies them to every session while each session keeps its own enabled flag. The page opens without a session ID, shows cumulative statistics across sessions, and opens the plugin data directory. The key test and key replacement use the shared `.env` file. Config and settings writes hold a private directory lock across read/modify/write, use UUID temporary names, and sync settings files before rename. The lock coordinates independent extension hosts and times out after two seconds. A crashed writer’s `.decision-write.lock` requires manual removal after verifying that its owner has stopped; Decision does not steal it. The Rust composer patcher is pinned to a specific Codex VS Code extension build and verifies its original hashes before installation. Revalidate the patch when Codex updates; reload VS Code after installing the control or patch.

The pinned host bridge resolves the public `vscode` module directly instead of relying on an unrelated minified bundle variable. Command lookup and execution run inside a promise so either failure produces a `BRIDGE_UNAVAILABLE` reply. The composer reports missing replies after ten seconds and allows recovery. A pending selection disables the button until its acknowledgement or timeout. The host integration regression sends the on/off action through the actual patch fragment and extension command to synthetic session storage.

Settings requests time out after ten seconds. A missing reply releases the form controls and asks the user to reopen settings to check saved values before retrying. Late replies cannot replace a later request. Activity cursors include file identity and the last consumed record. When the hook compacts the log, the control resumes after that record if it remains in the retained tail. It keeps the current view's counters and reads new events without replaying retained records.

Windows filesystem mode flags do not set Linux permissions through WSL UNC paths. The control opens each Linux path component without following links, verifies ownership, and sets private modes before publishing state. It repairs previously created session folders without changing selections. The control uses a compact dot when toolbar space is limited. It hides when the controls leave insufficient space.

The hook appends a small `classifying` event immediately before the first Decision request for one output. It carries no output text and does not add to completed-request totals. The controller increments a per-view `classificationPulse` counter; the webview flashes blue for 500 ms on a new counter value. Polling consumes each event once, so the pulse cannot be lost between status replies or restarted by relevance batches, final outcomes, classification skips, or connection probes. A new view starts at the current event cursor and does not replay historical pulses. Classification never writes `latest-decision.json`. The panel header contains the kept/total line count and a filtered or preview status. Batch metadata stays in the private snapshot and receipts.
