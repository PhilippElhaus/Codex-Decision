# VS Code control and panel

The companion extension contributes **Jev** to VS Code's bottom Panel. Hide it with the panel tab menu and restore it through **View → Open View… → Jev: Latest decision**. VS Code does not expose a contribution point for a direct custom top-level View menu entry. The view polls `PLUGIN_DATA/logs/latest-decision.json` every 500 ms while visible and starts empty until a new decision is created after this window starts. Older version 1 coarse snapshots remain on disk but are not shown.

A version 3 snapshot contains the latest completed Jev batch, with up to 250 judged source lines. Each row has a 120-character excerpt, Keep/Omit action, omission probability, exact-text probability, optional search relevance, and keep reason. The panel shows a 0–1 omission bar per row, with the other scores on hover. It also shows result totals and batch time. The snapshot is capped at 256 KiB and contains no API key, full raw output, or full receipt. Each completed batch publishes a processing snapshot; a failed later batch restores the previous snapshot. All `█` bars grow in parallel over 800 ms, values fade in over 170 ms, and the batch remains for another 1000 ms. Rapid updates coalesce to the latest snapshot. Same-batch status updates change totals in place. Long batches use the panel page scroll, with no nested scrollbar. Version 2 snapshots still render during an upgrade.

The Codex composer control is injected by a separately installed, version-pinned patch. It lets the user select output, test/build, and search/listing independently. If no key is available, **Connect Jev** asks for one without sending it as chat text. The key passes through the local bridge to the extension for testing or private storage. The settings page offers Monitor and Filter modes, per-route `Can omit` minimum and `Exact text needed` maximum, the optional search relevance keep guard, line and request counts, log retention, API key test, and an Open logs action. It no longer exposes Choice or group-level methods. A setting change applies to the next tool result. The first new plugin hook and extension versions must be installed together; the user reloads VS Code when ready.

The composer patch still runs through `vscode-control/patch_codex_webview.py` for the pinned Codex extension version. The filter hook itself is a prebuilt Rust binary. When the Codex extension changes its host bundle, the patch must be revalidated against that version before use.
