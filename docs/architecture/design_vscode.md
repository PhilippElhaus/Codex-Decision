# VS Code control and panel

The companion extension contributes **Jev** to VS Code's bottom Panel. Hide it with the panel tab menu and restore it through **View → Open View… → Jev: Latest decision**. VS Code does not expose a contribution point for a direct custom top-level View menu entry. The view polls `PLUGIN_DATA/logs/latest-decision.json` every 500 ms while visible and starts empty until a version 2 decision is created after this window starts. Older version 1 coarse snapshots remain on disk but are not shown.

A version 2 snapshot has one latest judged source line, up to five recent judged lines, bounded actual excerpts, two Noul probabilities for the latest line, result totals, and the elapsed time of the latest shared batch. It contains no API key, full raw output, or full receipt. Each completed batch publishes a processing snapshot. A failed later batch restores the previous snapshot. The five rows have fixed positions; the newest enters at the bottom and older rows shift up. The detail and two probability tracks keep stable positions. Full-block `█` cells fill in parallel over 800 ms, and percentages fade in afterward. The panel has dark and light theme colors and no internal scrollbars.

The Codex composer control is injected by a separately installed, version-pinned patch. It lets the user select output, test/build, and search/listing independently. If no key is available, **Connect Jev** asks for one without sending it as chat text. The key passes through the local bridge to the extension for testing or private storage. The settings page offers Monitor and Filter modes, per-route `Can omit` minimum and `Exact text needed` maximum, log retention, API key test, and an Open logs action. It no longer exposes Choice or group-level methods. A setting change applies to the next tool result. The first new plugin hook and extension versions must be installed together; the user reloads VS Code when ready.

The composer patch still runs through `vscode-control/patch_codex_webview.py` for the pinned Codex extension version. The filter hook itself is a prebuilt Rust binary. When the Codex extension changes its host bundle, the patch must be revalidated against that version before use.
