# VS Code control and panel

The optional control adds three switches beside the Codex composer and a **Jev** tab in VS Code's bottom panel. The active Codex route supplies a session ID. The extension hashes it into a directory name and reads only that session's config, activity, statistics, health, and latest decision. Switching threads changes the active directory and clears the view's activity. If the route has no usable session ID, the control reports a configuration error instead of writing a plugin-wide switch. The API key is intentionally shared by the local installation.

The composer indicator combines two different checks. The API probe tests the saved key and Jev endpoint. The hook writes `logs/hook-health.json` whenever it is invoked on an enabled session, including normal skips, completed decisions, and errors. Amber means no recent invocation has been seen in the current view; green means the API check passed and a recent hook invocation was observed; red means the API, config, status file, or hook failed. A connection test cannot turn an unverified hook green. The indicator returns to amber after two minutes without hook activity, so an old success cannot stand in for a current check. If the hook definition changed, Codex may require another `/hooks` review.

The panel reads `PLUGIN_DATA/sessions/<hash>/logs/latest-decision.json` while visible and starts empty in a new view. It accepts only the current version-3 snapshot. A snapshot contains up to 250 judged lines from the latest batch, each with a bounded excerpt, Keep/Omit action, omission and exact-text probabilities, optional task relevance, and keep reason. The 0–1 retention index is a local visual aid, not a Jev probability. Blue rows were cut; gold rows were kept. It never reads another session's panel file or a full receipt.

**Codex settings → Jev** stores Monitor/Filter mode, per-route cutoffs, search relevance guard, and log retention in the active session's config. The page also shows that session's cumulative statistics and opens its logs. The key test and key replacement use the shared `.env` file. The composer patch is pinned to a specific Codex VS Code extension build and verifies its original hashes before installation. Revalidate the patch when Codex updates; reload VS Code after installing the control or patch.
