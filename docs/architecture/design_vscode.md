# VS Code control and panel

The optional control adds three switches beside the Codex composer and a **Jev** tab in VS Code's bottom panel. A version-pinned bridge observes Codex's internal router and publishes the active local thread ID; the webview URL alone is not reliable. The extension hashes that ID into a directory name and reads only that session's config, activity, statistics, health, and latest decision. It creates an all-selected config once for a new local thread, then preserves the user's changes. Switching threads changes the active directory and clears the view's activity. On the new-thread or home screen, no session exists yet: the control stays neutral and disables the switches. A local thread route with an unreadable ID remains a configuration error instead of writing a plugin-wide switch. The API key is intentionally shared by the local installation.

The composer indicator reports the saved key and Jev API endpoint. The control sends a small synthetic Noul request. Green means it received a valid Jev answer; red means the key or request failed; amber means the request is pending. The probe runs without a session ID and when all filters are off. The hook writes `logs/hook-health.json` whenever it runs on an enabled session, including normal skips, completed decisions, and errors. Hook, config, and status-file errors appear in the session activity tooltip. The tooltip is hidden without a thread. An API check does not verify hook trust. Review `/hooks` after a hook update.

The panel reads `PLUGIN_DATA/sessions/<hash>/logs/latest-decision.json` while visible and starts with a small **Jev** label until a decision exists. It accepts only the current version-3 snapshot. A snapshot contains up to 250 judged lines from the latest batch, each with a bounded excerpt, Keep/Omit action, omission and exact-text probabilities, optional task relevance, and keep reason. The 0–1 retention index is a local visual aid, not a Jev probability. Blue rows were cut; gold rows were kept. It never reads another session's panel file or a full receipt. An unreadable decision is shown as a health fault in the composer, keeping the panel itself quiet.

**Codex settings → Jev** stores Monitor/Filter mode, per-route cutoffs, search relevance guard, and log retention in shared `PLUGIN_DATA/settings.json`. The Rust hook applies them to every session while each session keeps its own filter switches. The page opens without a session ID, shows cumulative statistics across sessions, and opens the plugin data directory. The key test and key replacement use the shared `.env` file. The Rust composer patcher is pinned to a specific Codex VS Code extension build and verifies its original hashes before installation. Revalidate the patch when Codex updates; reload VS Code after installing the control or patch.
