# Data handling

Codex Jev 0.4 uses independent line judgments. For each eligible physical source line, the Rust hook asks two Noul questions in a bounded shared request: **Can omit?** and **Exact text needed?** Each answer applies to its own line. The hook never uses a whole-result Choice or a search-group ranking to authorize deletion. Choice and Score are not used by this release.

The request includes a bounded cue from the latest user task, the route and command, the target line, and short neighboring context. A request is capped at 28,000 serialized UTF-8 bytes and 250 target lines; the actual number of lines per request is normally much lower. At most 12 sequential batches run within the hook deadline. Lines beyond the budget remain unjudged and are kept. An invalid answer, failed request, unavailable task cue, sensitive-looking result, unsupported format, or unsafe storage condition keeps the entire original result.

Each line may be omitted only when `can_omit` is at or above the route's `omit_min` and `exact_needed` is at or below `exact_max`. The defaults are 95% and 5%. Code also protects diagnostics, nearby context, completion totals, one representative of repeated lines, and the final line. A test/build result needs a completion marker. Search/listing accepts only direct, validated `rg -n`, `rg --json`, `rg --files`, and `git ls-files` results. JSONL structure records are kept. Kept text is copied from the exact original UTF-8 byte spans, including ANSI escapes and line endings. ANSI cleanup affects only the text shown to Jev.

After each completed batch, the hook publishes a small version 2 panel snapshot with at most five actual line excerpts and the latest line's probabilities. If a later batch fails, it restores the previous snapshot. When a result is shortened, the hook first saves the exact original under `PLUGIN_DATA/outputs/<session-hash>/<call-hash>.txt`, then returns kept lines with omission counts and that path. Monitor mode records decisions without changing tool output. Replacement also requires at least 1,024 bytes and a 30% reduction. The original and visible result are stored once in a private receipt; separate private batch records contain each request, response, elapsed time, and target IDs. `stats.json` distinguishes HTTP requests from lines seen, judged, kept, omitted, protected, and unjudged. Legacy version 1 snapshots do not populate the live panel.

The key is read from private `PLUGIN_DATA/.env` and sent in an HTTPS Authorization header. It is not included in receipts or panel snapshots. Receipts can contain raw tool output and task cues, so keep `PLUGIN_DATA` private. Managed receipts and batch records obey the log limit; saved originals remain until manually removed. Hosted web search and nested tool calls outside the local PostToolUse hook are unaffected.

The package contains a prebuilt Linux x86_64 Rust hook and `jevctl`; no Python interpreter is needed at hook runtime. Other execution environments need a native hook build. The separately installed VS Code composer patch remains a version-pinned local development tool.
