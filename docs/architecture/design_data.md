# Data handling

Local checks run before Jev receives text. If an eligible output fits within 20,000 serialized JSON bytes, the output filter sends all of it for judgment. Larger outputs are divided into bounded pieces, usually at line boundaries. Every character is covered. A record longer than one piece is split. Every checked chunk must pass each enabled method; one veto stops later request waves. The hook makes at most 128 chunk requests and keeps the full output if that limit would be exceeded. Test/build sends bounded samples of lines it may omit and retain. Output and test/build use three Noul judgments and one Choice by default. Their method settings can omit either type from the request. Search/listing uses Choice; its method setting can disable that request. A filter with no enabled methods keeps the original output. Score is not used. Search/listing sends a task cue and up to 12 path groups. That request is capped at 10,000 characters; it does not contain the full search result. A task cue can include up to 500 characters from the latest user request.

After approval, output capsules select source text from the full result using task terms, uncommon line templates, and result or source-location markers. The visible text includes original line numbers, omitted line ranges, and the saved-original path. Long selected lines are marked as truncated. Selection has a size budget and still requires substantial reduction. Search summaries retain task-aware examples and state explicitly that omitted entries are partial evidence. Structured `rg --json` matches are rendered as text for the coding agent; the original JSON remains in the saved file. JSON test/build adapters omit recognized routine events and preserve other events exactly. Unrecognized structured data falls back to conservative text handling or remains unchanged.

The full serialized Jev request is capped at 28,000 UTF-8 bytes, below Jev's 32k-token state plus longest-question limit. Oversized requests keep the original. The checks cannot prove that text is safe to send to an external API. Select an integration only if its text can go to Jev. Each Jev request has a three-second deadline by default. The hook has a 60-second timeout to allow bounded parallel chunk checks.

For eligible requests, the hook reads `JEV_API_KEY` from private `PLUGIN_DATA/.env` and sends it in an HTTPS Authorization header. The key does not enter tool text or decision logs. See [key setup](../setup/setup_credentials.md).

Before replacement, the hook saves the exact result at `PLUGIN_DATA/outputs/<session-hash>/<call-hash>.txt` with owner-only permissions. The shorter text gives Codex that path. Each Jev request creates one private JSON receipt under `PLUGIN_DATA/logs/YYYY-MM-DD-<session-hash>/`. The receipt filename contains UTC `HH-MM-SS`, microseconds, and a call index. It records the exact original and visible tool result, the request without its Authorization header, raw and normalized answers, mode, effective cutoffs, decision, and chunk position. A session `events.jsonl` and a bounded `logs/events.jsonl` activity index store metadata for the UI. `PLUGIN_DATA/stats.json` holds cumulative counts, including Jev checks, shortened results, estimated tokens saved, and average decision time. Its token estimate uses removed characters divided by four; it is not a billed-token count.

The default log limit is 50 MB. The settings page accepts 1–9999 MB or **Never delete logs**. After each event and receipt batch, the hook removes the oldest managed log files until their total fits the limit. Unknown files and links are not removed. **Never delete logs** disables pruning and index truncation. A lower limit takes effect on the next Jev event. Saved originals under `outputs/` stay until you remove them and do not count toward the log limit. Existing root `events.jsonl` remains read-only legacy data; its counters are imported on the first new event. Keep the plugin data directory private because receipts contain raw tool output.

Hosted web search does not pass through this hook. A nested JavaScript tool call gives the original result to its script. Jev saves model-visible tokens only when the raw tool text would reach Codex. The VS Code control estimates reduction from character counts; it does not report billed tokens.
