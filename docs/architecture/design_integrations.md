# Integration behavior

The Rust PostToolUse hook has three independently selectable routes. The VS Code control selects all three for each new local thread; a standalone hook requires explicit configuration. Eligible source lines receive independent Noul judgments; a validated pair of probabilities and deterministic protections decides whether each line stays. Search results receive a third task-relevance judgment. [Data handling](design_data.md) describes the request and storage limits.

| Route | Local eligibility and protection | Visible result in Filter mode |
| --- | --- | --- |
| Output | Plain text from other local command, read, and tool results; size and sensitive-data checks; diagnostics and context protected. | Exact kept lines in source order, omission ranges, and saved-original path. |
| Test/build | Direct test/build commands or named test/build tools with a completion marker; diagnostics, completion totals, and nearby context protected. | Exact kept log lines and omission ranges. |
| Search/listing | Direct search/listing commands or named search/listing tools; numbered and JSONL records validated, structure protected. | Exact kept match/path records and omission ranges. |

`line_policy` contains `omit_min` and `exact_max` as whole percentages for each route. A line is removable only when `p_can_omit >= omit_min / 100` and `p_exact_needed <= exact_max / 100`, and no protection applies. The defaults remain 95 and 5. The [reviewed live demo](../development/quality_demo.md) compares alternatives without changing installed settings. Search `task_relevant` is always judged and logged; optional `search_relevance.guard_enabled` keeps a line when `p_task_relevant > relevant_max / 100`. Its default is off with a 5% cutoff. It cannot independently authorize omission. Protected lines are excluded as targets, reducing request work; unjudged lines are kept. `observe` records judgments while returning the full output; `replace` saves the original and may return a shorter result when the size and savings checks pass. If any batch fails validation, the hook returns the full result.

The hook matcher observes every supported local PostToolUse event. A deterministic classifier assigns one route from the direct shell command (`Bash` or `exec_command`, including `cmd` input), then from a local tool's action name, and finally to Output for other plain text. Shell parsing accepts quoting, environment assignments, a leading `cd … &&`, and a simple shell `-c` wrapper. It rejects pipelines, redirections, command substitutions, and ambiguous multiple commands. Search commands include `rg`, `grep`, `find`, `fd`, `ls`, and Git search/listing forms. Structured or mixed-media responses, mutating tool actions, sensitive-looking text, unsupported formats, and short results are not sent to Jev. A disabled route never falls through to another switch. Plain-string local responses may be replaced; metadata-bearing command objects and MCP text blocks are previewed only unless MCP replacement is explicitly enabled. Without a usable transcript task, the hook can preview using a bounded input cue but never replace the result.

[Noul](https://docs.typesafe.ai/primitives/noul) supplies independent yes/no probabilities for each line. [Choice](https://docs.typesafe.ai/primitives/choice) optionally screens large general Output results before line checks; it never authorizes deletion itself. Test/build and search/listing use the established deterministic routes and skip this extra request. The VS Code settings page writes schema-1 shared settings; the three switches remain in each session’s schema-2 config. Rust and Node validate both formats against [one contract](../../vscode-control/config-contract.json). Unknown or outdated config fields are errors rather than silently disabled filters. See the [architecture diagram](../images/jev-architecture.svg).

The Rust `jevctl evaluate-quality` command replays reviewed receipts and reports per-route and per-split evidence loss and gate trials, including stricter omission thresholds and the search relevance guard. Trials are observational and do not change settings.
