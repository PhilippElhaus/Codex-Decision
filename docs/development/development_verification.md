# Verify a change

Use the release checks in [tests/README.md](../../tests/README.md). Run the Rust process suite after hook or storage changes, Node tests after control changes, and the Edge browser smoke test after any composer or settings change. Build with `./scripts/build_submission.sh`, which writes Cargo artifacts in the user cache and the plugin ZIP in `.local/submission/`. Use `./scripts/build_control.sh` for the VSIX. Both build scripts call `scripts/verify_packages.py` to check exact archive entries and packaged source bytes. The hook build accepts only Linux x86_64, selects the `x86_64-unknown-linux-gnu` target explicitly, and verifies ELF headers and compiled versions before packaging. The control build pins VSCE 4.0.0. Existing archives are retained; advance the version before rebuilding. CI runs these package checks and the browser harness in Chromium. Keep the native Edge check for Windows releases.

Before deployment, check the plugin ZIP and VSIX, then install the changed components. Run `decisionctl check-hook-trust --cwd <repository>` against the installed hook. Codex binds trust to a hook definition hash, so a hook upgrade is incomplete until `/hooks` shows the current definition as trusted and enabled. Start a new thread and run an eligible local command. Verify that Decision is enabled and that a fresh hook-health record and decision appear for that session. Repeat from a second Codex window: its enabled flag should be independent, its counters should start empty, and changing its enabled flag should not change the first window. Navigate between existing threads without reloading the webview to confirm that the control follows Codex's internal router.

The hook returns the full original result on a failed Decision request, invalid answer, unsafe task, or storage error. `logs/hook-health.json` identifies the last invocation, skip, success, and error without storing the key or tool text. The indicator reports only the API check; a hook error appears in the session tooltip. Normal skips include short, structured, unsupported, and sensitive results. Keep the `/hooks` check in every release procedure; Decision never edits Codex's trust database.

For reviewed quality cases, create a private JSON array such as:

```json
[{"id":"failing-test-1","split":"holdout","receipt":"/private/receipt.json","required_lines":[5,6,9],"task_solved":true,"baseline_task_solved":true}]
```

Run `decisionctl evaluate-quality --cases <private-cases.json>`. It reports actual required lines lost, proposed omissions and required losses separately, characters saved, and gate trials per route and split. Monitor and rejected candidates never count as actual evidence loss. These trials do not change settings or prove future task success. Receipts may contain private tool output; keep cases outside the repository. The current live runner sends only synthetic output and reads the installed key in memory.

The [pipeline optimization pass](pipeline_optimization_2026-10-07.md) records exact-byte checks, allocation measurements, interruption recovery, concurrent faults, and bounded query trials. The [selection quality pass](quality_pass_2026-10-06.md), [initial two-stage evaluation](two_stage_evaluation.md), and [historical demo](quality_demo.md) retain their dated results; their trials do not calibrate current relevance. Release builds strip symbols and use full link-time optimization with one codegen unit to remove unused code across crates. They keep the default speed optimization level and HTTPS. Link-time optimization increases release build time. The build uses the locked dependencies with unused regex, JSON-helper, gzip, and Chrono serialization features disabled.

The hook entrypoint delegates to modules under `rust/decision/src/bin/decision-hook/`. Keep route selection, structured evidence, API validation, private storage, retention, telemetry, snapshot rollback, receipt publication, and orchestration in their owning modules. Offline process tests exercise the complete binary.

Keep current packages and designated rollback packages in `.local/submission/`. Remove superseded packages only after checking their contents and rollback records. Do not remove installed plugin state, saved originals, or composer rollback files as package cleanup.

Version 0.10.1 uses [batching verification](batching_verification.md); the [initial two-stage evaluation](two_stage_evaluation.md) is the prior single-request baseline. Use `scripts/two_stage_quality.cjs` for current Choice/relevance requests. The historical `scripts/demo_quality.cjs` now delegates to this current runner; historical report metrics remain dated evidence. Current quality receipts use version 3 and support relevance-cutoff replay. Keep legacy omission/exact-text trials only for version-2 receipts.
